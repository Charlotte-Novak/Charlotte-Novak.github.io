書上的惡劣例子：

spam = 4
2 + 2 == spam and not 2 + 2 == (spam + 1) and 2 * 2 == 2 + 2

這是作者的惡作劇，grok說：正常人不會這樣寫程式，這是故意刁難讀者的例子。🤣

解釋 1：正常人會寫的版本，跟上面是一樣意思的：

spam = 4
a = (2 + 2 == spam)                    # 4 == 4
b = (2 + 2 != (spam + 1))             # 4 != 5   ← 用 != 更直覺
c = (2 * 2 == 2 + 2)                    # 4 == 4

result = a and b and c
print(result)                               # True

解釋 2：

result = (2 + 2 == spam) 為真
and (2 + 2 != spam + 1) 為真
and (2 * 2 == 2 + 2) 為真
3 個都是 true，所以最後：
print(result)   # True

以下來說，這例子的核心惡劣之處！

and not 2 + 2 == (spam + 1)

這裡的 not 有優先權，計算時實際會被解析成：

not 2 先計算 → False（因為 2 是 Truthy）
然後 False + 2 → 變成 2（因為 False 當成 0）
再繼續後面的比較 → 整個表達式會變成奇怪的結果，但不會直接報錯！
書上那種寫法不會 SyntaxError，但非常容易產生非預期的行為。

spam = 4
# 書上的寫法（危險！）
expr1 = 2 + 2 == spam and not 2 + 2 == (spam + 1)
print("書上寫法:", expr1)   # 實際執行結果可能出乎意料

# ✅ 推薦寫法（明確加括號）
expr2 = (2 + 2 == spam) and (not (2 + 2 == (spam + 1)))
print("推薦寫法:", expr2)

鐵律：只要有 not，永遠建議用括號包起來，尤其是和比較運算混用時。

這就是為什麼這例子「惡心」的原因 —— 它不會直接出錯，但結果很可能不是作者原本想表達的意思。
